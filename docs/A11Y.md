# Accessibility checklist (WCAG 2.2 AA target)

Critical paths should remain keyboard-usable and axe-clean. Automated smoke: `npm run build && npm run test:a11y` (CI runs lint + unit + build + axe).

---

## CI / automated

- Playwright + axe (`tests/a11y.spec.ts`): home, privacy, terms; skip link; 320px layout; mobile menu Escape.
- Gate: **serious + critical** violations fail CI.
- Tags: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`.
- **Coverage note:** axe CI is shell/legal-heavy. Checkout and `/admin` are **manual** keyboard/smoke only until additional specs land.

When you change shell, forms, checkout, or brand colors, re-run a11y locally before merge.

---

## Editor checklist (Sanity content)

Use this before publishing events, galleries, or pages.

### Images

- [ ] Every image has meaningful **alt text** (not “image1” / filename).
- [ ] Decorative images: empty alt only if the CMS/image component supports decorative; prefer real descriptions for heroes and posters.
- [ ] OG / social images are readable at small size (title not cut off).

### Text & structure

- [ ] One clear **H1** per page (event title, page title).
- [ ] Headings in order (do not skip from H2 to H4 for decoration).
- [ ] Links describe destination (“Get tickets” not “Click here”).
- [ ] Body copy has enough contrast on dark backgrounds (see tokens below).

### Video

- [ ] Prefer YouTube/Vimeo (player a11y + captions when available).
- [ ] Title + description present so the page makes sense without autoplay audio.

### Events / ticketing copy

- [ ] Price, date, venue stated in text (not only in the image).
- [ ] Sold-out / cancelled status visible without color alone.

---

## Engineering checklist (UI changes)

### Landmarks & focus

- [ ] Skip link → `#main-content` works (Tab from load, Enter).
- [ ] `header` / `main` / `footer` landmarks present.
- [ ] Visible `:focus-visible` rings on interactive controls.
- [ ] Modals/menus: Escape closes; focus returns to the control that opened them.
- [ ] No keyboard traps on checkout or admin.

### Forms (checkout, Genesis, contact)

- [ ] Every input has a visible `<label>` (or `aria-label`).
- [ ] Errors associated with fields (`aria-describedby` / `aria-invalid`) and summarized in an `aria-live` region if needed.
- [ ] Required fields indicated in text, not color alone.
- [ ] Legal checkboxes (Privacy / Terms) reachable and labeled.

### Motion & mobile

- [ ] Honor `prefers-reduced-motion` for non-essential animation.
- [ ] Usable at **320px** width without horizontal scroll of the page shell.
- [ ] Touch targets ≥ ~44×44px where practical.

### Color & brand

Placeholder tokens (AA-oriented dark theme) in `app/globals.css`:

| Role | Approx. |
|------|---------|
| Background | `#0a0a0a` |
| Foreground | `#f5f5f5` |
| Accent | `#5eead4` |

- [ ] When brand kit lands, re-check **contrast** (text/icons on bg, accent on bg, error text).
- [ ] Do not rely on color alone for status (pair with text/icon).

### Admin

- [ ] `/admin` tables and filters usable with keyboard.
- [ ] Destructive actions (reconcile, export) have clear labels; success/error messages announced.

## Manual smoke (pre-release)

1. Keyboard-only: home → event → checkout fields → submit (test mode).
2. Screen reader spot-check (VoiceOver / NVDA): event heading, price, primary CTA.
3. 200% browser zoom: layout still readable.
4. Mobile menu open/close with Escape.

---

## Reporting issues

Log a11y bugs with: URL, browser, assistive tech (if any), steps, expected vs actual. Prefer fixing serious/critical before the next event on-sale.
